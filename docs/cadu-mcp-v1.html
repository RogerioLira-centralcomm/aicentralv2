O Cadu organiza trabalho, contexto e agentes.

Uma arquitetura operacional para conversar, criar, pesquisar e manter projetos vivos. O Harness governa a execução; o MCP expõe capacidades seguras; o CentralX preserva contexto, recursos, permissões e observabilidade.

Harness é o cérebro operacional. MCP é a fronteira.

Cadu UIPedido e objeto ativo
HarnessRota, contexto, plano e budget
Tool LayerNative tools, skills e MCP
CentralXPersiste, versiona e observa

O MCP não decide como o Cadu pensa. Ele padroniza o acesso a dados e capacidades. O Harness controla Conversation, Turn, contexto, seleção de ferramentas, execução, artifacts, permissões, eventos e políticas de resposta.

Dify não é a fonte canônica de histórico, autorização, custo ou artifacts. Essas responsabilidades pertencem ao CentralX.

Projeto é um agregado transversal, não uma pasta

Uploads, PDFs, imagens geradas, vídeos, briefings, planos, relatórios, links e artifacts entram em um registro contextual único. O objetivo é organizar a informação como um sistema de arquivos inteligente: cada movimentação reconcilia identidade, classificação, relações, versões e índice.

Resource Registry

Registra origem, projeto, marca, tipo, finalidade, versão, hash, permissões e relações com outras entregas do Cadu.

Context Graph

Conecta fontes, decisões, planos, criativos e resultados para que a resposta recupere uma linha concreta de contexto, não arquivos isolados.

Rotina após criar, mover, substituir ou arquivar

evento → autorização → hash/deduplicação → classificação → metadados
       → relações contextuais → versão → índice autorizado → observabilidade

A organização pode ser automática; o consentimento para usar conteúdo como conhecimento não. Um classificador sugere categoria, mas nunca promove sozinho um anexo para fonte indexada.

Três modos de execução, não três agentes desconectados

ModoFinalidadeExecuçãoEstado
fastResposta curta, ajuste e síntese simplesContexto mínimo, 0–1 tool e uma chamada de modeloImplementado
analysisDiagnóstico, comparação e recomendaçãoContexto seletivo, evidências e tools de domínioImplementado
agenticTrabalho com várias etapas e artifactsPlano persistido, checkpoints, ações, retomada e budget explícitoFundação

O runtime V2 formaliza os três modos no contrato, roteamento, budgets, persistência e seletor da interface. O legado continua recebendo a tradução compatível focus, analysis e deep. No modo agentic, plano, etapas e checkpoints já são persistidos; retomada automática e confirmações humanas entre etapas ainda são o próximo endurecimento.

O Provider Registry já separa cadu-fast, cadu-analyst e cadu-operator, com configuração e sessão Dify próprias por Conversation. Enquanto as novas credenciais não forem cadastradas, cada modo pode usar o app V2 atual como fallback controlado.

Observabilidade é um produto interno do CentralX

Cada Turn precisa ser explicável sem depender do painel do provider. O CentralX deve registrar a sequência completa da execução e oferecer visão operacional por cliente, projeto, rota, capability, modelo e período.

DimensãoO que registrarEstado
Turnrota, modo, política, estado terminal e objeto ativoImplementado

Consumotokens, créditos, custo por provider, etapa e TurnParcial

O CentralX agora registra o journal ordenado, runtime selecionado, versão de configuração, latência total e do provider, primeiro token, tools, tokens, créditos, custo estimado e estado terminal. A interface administrativa oferece alertas iniciais, resumo, distribuição por modo, runs recentes e timeline detalhada. Ainda faltam métricas de qualidade e reconciliação financeira precisa por provider.

Conexão inicial

O endpoint é /workspace/mcp. A versão atual usa JSON-RPC sobre HTTP e uma delegação assinada de cinco minutos, emitida por uma sessão autenticada no Cadu. O catálogo é evolutivo: novas capacidades entram por domínio depois de autorização, idempotência, cobrança e retorno estarem estabilizados.

Emitir uma delegação

POST /workspace/api/v2/mcp-token
X-CSRF-Token: <csrf da sessão>
Content-Type: application/json

{
  "exposure": "customer_agent",
  "surface": "workspace"
}

Inicializar

POST /workspace/mcp
Authorization: Bearer <token>
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "initialize",
  "params": { "protocolVersion": "2026-07-28" }
}
A delegação curta atende o Cadu e integrações iniciadas dentro do produto. OAuth, refresh token e revogação por aplicativo são requisitos anteriores à distribuição pública.

Artefatos versionados

Briefings, documentos, notas, resumos, planos, cenários e pesquisas nascem como rascunho. Uma atualização exige a versão conhecida pelo agente; se outra pessoa editar antes, o servidor recusa a gravação.

{
  "jsonrpc": "2.0",
  "id": 12,
  "method": "tools/call",
  "params": {
    "name": "artifacts.create_draft",
    "arguments": {
      "request_id": "0199dff8-85ac-72cc-81df-49d221884703",
      "type": "brief",
      "title": "Briefing da campanha",
      "content": { "objective": "Gerar demanda qualificada" }
    }
  }
}

artifacts.update_draft recebe expected_version e cria uma nova versão. A publicação externa ainda não faz parte do catálogo atual.

Arquivos são recursos inteligentes do projeto

Fonte de conhecimento é apenas uma das finalidades possíveis. Um arquivo também pode ser entrega, referência, ativo de marca, documento de trabalho, evidência, relatório ou material gerado pelo Studio. Ele permanece ligado ao projeto, à marca, às versões e às relações com outros recursos do trabalho diário.

Usar como fonte de dados

PDF, DOCX, TXT, CSV, Markdown, JSON e HTML têm o texto extraído, indexado e disponibilizado para pesquisa e respostas com contexto do projeto.

use_as_knowledge: true

Somente anexar

O arquivo permanece privado no projeto, mas seu conteúdo não é enviado ao índice nem utilizado como evidência automática. Imagens também podem seguir este caminho.

use_as_knowledge: false
A escolha é explícita em cada upload. O nome do arquivo ou seu formato nunca fazem o sistema presumir consentimento para usar o conteúdo como fonte.

A classificação é independente dessa escolha. Cada item recebe uma categoria revisável: briefing, pesquisa, plano de mídia, relatório, ativo de marca, referência, contrato, planilha ou outro. A lista de projetos devolve em summary as contagens de fontes, anexos, artifacts, planos, relatórios, imagens e vídeos associados.

Regra de produto: formato não compreendido nunca vira “fonte vazia”. projects.inspect_file_support informa unsupported ou needs_adapter antes da transferência. O upload MCP atual não aceita esse binário; quando houver armazenamento genérico, ele poderá ser preservado sem alegar que foi processado.

Upload em duas etapas

Binários não atravessam o JSON-RPC. A ferramenta prepara uma autorização curta e o cliente envia o arquivo por multipart para o endpoint informado.

0. Verificar compatibilidade

tools/call → projects.inspect_file_support

{ "filename": "investimento.xlsx", "mime_type": "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet" }

→ { "status": "needs_adapter", "format_family": "spreadsheet",
    "can_attach": false, "can_index": false }

1. Preparar

tools/call → projects.prepare_source_upload

{
  "request_id": "0199dff8-85ac-72cc-81df-49d221884703",
  "use_as_knowledge": true,
  "category": "brief"
}

2. Enviar

POST /workspace/mcp/uploads
Authorization: Bearer <mesma delegação MCP>
Content-Type: multipart/form-data

upload_token=<token retornado>
file=@briefing.pdf

Limite inicial: 15 MB. Para indexação são aceitos PDF, DOCX e formatos textuais. Como simples anexo, também são aceitos PNG, JPEG, WebP e GIF.

Logo da marca

brands.prepare_logo_upload gera uma autorização de dez minutos. O cliente envia um único PNG, JPEG ou WebP de até 5 MB para /workspace/mcp/brand-uploads. O upload define o ativo como logo principal, mas não inicia auditoria.

POST /workspace/mcp/brand-uploads
Authorization: Bearer <mesma delegação MCP>
Content-Type: multipart/form-data

upload_token=<token retornado>
file=@logo.png

A criação e a auditoria exigem confirmed: true. A auditoria é uma etapa separada: brands.start_audit exige administrador, saldo disponível, site oficial e confirmação explícita. Consulte o progresso com brands.audit_status.

Limites de segurança

TenantOrganização e usuário vêm do token assinado, nunca dos argumentos.
ProjetoO upload é vinculado ao projeto selecionado e o token expira em dez minutos.
ArquivosNome normalizado, limite de tamanho, extensão permitida e validação básica do conteúdo.
ConhecimentoSomente arquivos com consentimento explícito são extraídos e indexados.
CréditosA indexação usa o conector compartilhado do Cadu; anexar sem indexar não cobra processamento de IA.
MutaçãoAgentes externos criam e editam rascunhos; arquivamento continua restrito ao agente interno.

Planner: capacidades atuais e expansão MCP

O Planner já funciona como um domínio completo dentro do Cadu. O MCP publica leitura de planos, catálogos, briefing e plano de mídia, além da primeira ação controlada: o Link Tester. As demais funções serão abertas em grupos pequenos, reaproveitando os serviços existentes e mantendo autorização por projeto.

O Link Tester pertence ao Reports. reports.link_test exige confirmação e request_id, reutiliza a análise canônica e devolve evidências estruturadas sem expor o token de compartilhamento. A leitura do histórico usa reports.list_link_tests e reports.get_link_test; novos testes não dependem de projeto do Planner.

O Studio aplicará a estrutura de prompts do Cadu, usará os créditos do usuário e devolverá um asset persistido pelo MCP. Prompts internos, chaves e respostas brutas de providers não serão expostos.

Próximos endurecimentos, na ordem correta

  1. Agentic executor: ampliar para outros domínios o fluxo já ativo no Link Tester: proposta selada, confirmação, execução idempotente e receipt.
  2. Adapters de eventos: ampliar hooks de movimentação, substituição, vínculo e arquivamento para Planner, Studio e Reports.
  3. Context Graph semântico: enriquecer as relações determinísticas atuais com proveniência, decisões e derivações entre versões.
  4. Observabilidade avançada: adicionar métricas de qualidade, feedback, custo real por provider e filtros exportáveis; os alertas operacionais iniciais já estão ativos.
  5. Turn Items: consolidar mensagens, activities, actions, tables, artifacts e errors em um envelope canônico, preservando as tabelas atuais.
  6. Abertura externa: adicionar OAuth, revogação por aplicativo, idempotência integral, rate limits e recursos MCP.
OCR e conhecimento visual, publicação externa de artifacts, vídeo generativo e adapters MCP do Studio continuam bloqueados até terem consentimento, preço, armazenamento, retenção e política de reembolso definidos. Criação de imagens e Creative Analyzer já funcionam dentro do Cadu.
